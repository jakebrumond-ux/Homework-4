Welford’s Recurrences and Sampling Statistics

Derive the one-pass update for the sum of squares and the variance, then test how sample means and variances behave across many simulated hackers.

1Exercise 1 – Welford’s Recurrence Formulas

Let Mk be the mean of the first k values and SSk = Σ(xi − Mk)². Start from Knuth’s mean update and put d = xk − Mk−1.

  1. Knuth’s meanMk = Mk−1 + d / k
  2. Rewrite SS using SSk = Σx² − k·Mk²SSk − SSk−1 = xk² − k·Mk² + (k−1)·Mk−1²
  3. Expand k·Mk² = k·Mk−1² + 2·Mk−1·d + d²/kSSk − SSk−1 = xk² − Mk−1² − 2·Mk−1·d − d²/k
  4. Simplify with xk² − Mk−1² = d² + 2·Mk−1·dSSk − SSk−1 = d² − d²/k = d²·(k−1)/k
  5. Use xk − Mk = d·(k−1)/k, so the increment equals d·(xk − Mk).
RESULT SSk = SSk−1 + d·(xk − Mk)   (M0 = SS0 = 0) s²k = ((k−2)/(k−1))·s²k−1 + d²/k   for k ≥ 2, with s²k = SSk/(k−1)

Code – three lines of core logic

function welford(xs) {
  let M = 0, SS = 0, k = 0;
  for (const x of xs) {
    k++;
    const d = x - M;        // d = x_k - M_{k-1}
    M  += d / k;            // Knuth's mean update
    SS += d * (x - M);      // Welford's SS update
  }
  return [M, SS / (k - 1)]; // sample mean, unbiased sample variance
}

2Exercise 2 – Sampling Mean and Variance

Scores are drawn from a discrete uniform distribution on {0, 1, …, 10}, so μ = 5 σ² = (11² − 1)/12 = 10 μ₄ = 178 Each of m hackers attacks n systems and gets n scores. Welford gives each hacker’s sample mean and variance, then we average across hackers.

Code

const MU = 5, SIGMA2 = 10, MU4 = 178;

function mulberry32(a) {            // small seeded RNG
  return () => {
    a |= 0; a = a + 0x6D2B79F5 | 0;
    let t = Math.imul(a ^ a >>> 15, 1 | a);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

function experiment(n, m, rand) {
  const means = [], vars = [];
  for (let h = 0; h < m; h++) {
    let M = 0, SS = 0;                     // inline Welford
    for (let k = 1; k <= n; k++) {
      const x = Math.floor(rand() * 11);   // score in 0..10
      const d = x - M; M += d / k; SS += d * (x - M);
    }
    means.push(M); vars.push(SS / (n - 1));
  }
  const avg = a => a.reduce((s, v) => s + v, 0) / a.length;
  const sd  = a => { const mu = avg(a); return Math.sqrt(avg(a.map(v => (v - mu) ** 2))); };
  return {
    n, avgMean: avg(means), avgVar: avg(vars), sdMean: sd(means), sdVar: sd(vars),
    thMean: Math.sqrt(SIGMA2 / n),                                  // sigma / sqrt(n)
    thVar:  Math.sqrt((MU4 - SIGMA2 ** 2 * (n - 3) / (n - 1)) / n)  // sd of s2
  };
}

3Conclusions

01

Both estimators are unbiased

E[x̄] = μ and E[s²] = σ². The averages over hackers land on 5 and 10 even for n = 5. This needs the n − 1 divisor; dividing by n gives σ²(n−1)/n, too low for small n.

02

Why it matters for inference

μ and σ² are usually unknown. This justifies estimating them from a single trajectory, and underlies confidence intervals, t-tests and the standard error s/√n.

03

Larger n, less variability

Var(x̄) = σ²/n, so the spread shrinks like 1/√n. Var(s²) is also of order 1/n, with a constant that depends on μ₄, so variance estimates are noisier than mean estimates.

04

m versus n

Raising m only sharpens the average over hackers, which is already centred on the truth. Raising n is what improves each individual estimate (consistency, plus CLT normality of x̄).

05

Why Welford

One pass, O(1) memory, and no catastrophic cancellation like the naive Σx² − n·x̄² formula.
